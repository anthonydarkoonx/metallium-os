# The ROCK 3C board and the general tree
> The board folder is now its own repository, https://github.com/anthonydarkoonx/metallium-os-rock3c (GPL-2.0-only). Its scripts
> find this tree through `METALLIUM_OS`; the rules below still hold. Paths `rock 3c test/...` below mean that repository.


**Rule (user, 2026-11-15):** `rock 3c test/` holds ONLY the board's drivers and platform code. Every OS-level change (kernel, programs, UI, memory policy, tests, libs)
is made in the general tree and nowhere else. Nothing is copied back out of `rock 3c test/` (it is the GPL-2.0 exception, one-way flow: see its EXCEPTION.md).

## How the board is built

`rock 3c test/scripts/build-metal.sh` copies the general `kernel/src` and `user/src` into `rock 3c test/metal/stage/`, then lays `rock 3c test/metal/overlay/`
over them: **a file in the overlay replaces the general file of the same name**; files only in the overlay are the board's own. `metal/stage` is generated (never edit it).
The libs come straight from `../libs` (the board no longer has copies).

Platform differences go through hooks (a function in `platform.rs`, which each platform supplies), never through a edited copy of a shared file. The board's drivers are
modules of its `platform.rs` (`kernel/src/platform/*.rs`), so general code never names them.

## What the board folder holds now (`rock 3c test/metal/overlay/`)

Kernel (`overlay/kernel`): `linker.ld` (the board's link address), `src/boot.S` (with the arm64 Image header U-Boot wants), `src/gic.rs` (GICv3), `src/uart.rs`
(the DesignWare UART), `src/platform.rs` (the board's parameters and hooks, its kernel object numbers and `boot_caps`) and `src/platform/*.rs` (display/HDMI,
xHCI/USB, SD, Ethernet probe, TRNG, device tree, the serial loader). Nothing else: every other kernel file is the general tree's.

User (`overlay/user`): `gpu.rs` (VOP2 display driver and the 1920x1080 size), `kbd.rs` (USB HID input driver), `blk.rs` + `blk/` (RAM disk of the initrd, written through to
the eMMC/SD card), `netdrv.rs` (the GMAC Ethernet driver), `audiod.rs` (the I2S audio service). Everything else is the general tree's.

The hooks the general tree offers a platform: `platform.rs` of the kernel (see the general file: constants `RAM_BASE`, `LINK_BASE`, `HAS_SMMU`, `SWAP_*` ..., `map_devices`,
`psci_power`, `psci_cpu_on`, `exit_machine`, `early_boot`, `entropy_report`, `init_devices`, `irq`, `probe_devices`, `boot_caps`, `spawn_extra_tasks`); for user space the
driver modules `blk.rs`, `gpu.rs`, `kbd.rs`, `netdrv.rs`, `audiod.rs` (the general tree has the QEMU/virtio or "no device" version of each; a platform replaces the file).

## Moved into the general tree (2026-11-15, was only in the board's copy)

Original code, written from specifications (RFC 4330 SNTP, HTTP/1.0, the WAV format); none of it was derived from Linux or U-Boot source, so it carries the project
licence (the old SPDX GPL header was dropped). The hardware drivers stay GPL in the folder. Provenance for these is in PROVENANCE.md.

- kernel: `SLEEP_US` (44) and `SETTIME` (45) system calls, `timer::set_wall`, `spawn::boot_net_page` and the shell's network session, the audio service endpoint (`EP_AUDIO`) and role 20,
  platform-object numbers 52..=63 reserved, `NIRQ` 4, `DESKTOP_HEAP_PAGES` 16000 (a cap), swap store size from the platform.
- user: `audio.rs` (ring protocol, `Player`, WAV parsing, `Converter`) with `audiod.rs` as the per-platform driver, `httpc.rs`, the shell's `play` and `download`,
  network time in `netd.rs` (only on a machine with no wall clock), the desktop's adaptive idle (`sleep_us`) and window-refusal messages, surfaces sized from the screen, the
  pager started in the interactive session, `blk.rs` (the virtio disk moved out of `main.rs`).
